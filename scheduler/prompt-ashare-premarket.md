## 任务（按序完成，控制工具次数）

### 0. 市场状态判断（必须，放在「昨日大盘复盘」之前）

基于 **昨日收盘** 数据判断当前 A 股环境。章节标题：`## 市场状态判断（必须）`。
缺关键数据标「未获取」并下调对应分项与总评置信度；**不编造均线/量能**。

#### 市场周期（六选一，只能选一个）

- 下跌趋势
- 震荡筑底
- 反弹初期
- 反弹确认
- 主升阶段
- 高位风险

#### 判断依据（四块都要写，能拿到的写数字）

1. **上证指数位置**：相对 MA5 / MA10 / MA20 / MA60（站上/跌破/纠缠；能算则算）
2. **成交量**：两市合计成交额 vs **近 5 日均量** → 放量/平量/缩量
3. **市场情绪**：涨停数、跌停数、涨跌家数比（或上涨家数/下跌家数）
4. **主线持续性**：昨日主线是否延续（与近几日对比一句）；对齐用户「主线科技/AI」但不硬套

#### 市场评分（100 分制，分项打分后求和）

| 分项     | 满分 | 打分要点（示例，可微调）                                        |
| -------- | ---- | --------------------------------------------------------------- |
| 趋势     | 0–25 | 多头排列/站上均线给高分；空头/跌破 MA5·MA20 给低分              |
| 量能     | 0–25 | 相对 5 日均量健康放量且价涨给高分；缩量下跌/天量滞涨扣分        |
| 赚钱效应 | 0–20 | 涨停多、跌停少、涨跌比健康给高分                                |
| 主线强度 | 0–20 | 主线清晰且持续给高分；杂乱轮动/一日游扣分                       |
| 风险     | 0–10 | **分越高=环境风险越可控**（情绪极端、高位加速、监管冲击等扣分） |

输出固定块：

```
市场评分：XX/100（置信度：高/中/低）
当前状态：<六选一>
对应策略：防守 | 轻仓试错 | 积极参与 | 进攻
```

策略映射（按总分）：

| 分数  | 策略     |
| ----- | -------- |
| 0–40  | 防守     |
| 40–70 | 轻仓试错 |
| 70–85 | 积极参与 |
| 85+   | 进攻     |

策略须与用户 A 股规则对齐：指数线下偏防守；线上才谈试错/参与；不代选股；不追加速。

### 1. 昨日大盘复盘

拉取上证 / 深成指 / 创业板指的 **上一交易日收盘** 数据：

- 点位、涨跌幅、成交额（能拿到则写）
- 对照用户规则：上证是否在 **5 日均线**上方（能算则算；算不了标「未获取」）
- **事实**与**解读**分开写；解读对齐「趋势为王 / 指数线上仓位可偏重、线下偏轻」
- 章节标题用：`## 昨日大盘复盘`
- **成交额总量不够**：量能放缩、北向、主力行业流向一律写入下一节「昨日资金面」，本节只保留指数点位与涨跌家数等价格结构
- 均线详细数字可与第 0 节复用，避免重复注水

### 1b. 昨日资金面（必做，不可只用总量成交额敷衍）

在大盘复盘之后，单独成章：`## 昨日资金面`。数据优先 **东方财富 / 同花顺**「资金流向」「北向资金」口径；写明来源；查不到标「未获取」，不编造。

必须覆盖以下三块（缺一不可，缺则写未获取）：

1. **量能结构（放量 / 缩量）**
    - 沪深两市合计成交额（昨）
    - 对比：较前一交易日变化（金额 + 百分比）；若能拿到，再比 **近 5 日日均成交额**（或近 5 日区间）
    - 明确结论一句：**放量 / 平量 / 缩量**（相对哪条基准写清楚）
2. **北向资金**
    - 昨日北向合计净流入/流出（亿元）；能拆沪股通/深股通则拆
    - 若有近 5 日累计，可附一行；无则只写单日
3. **主力资金 · 行业偏好**
    - 主力净**流入**行业 TOP 3（名称 + 净流入额）
    - 主力净**流出**行业 TOP 3（名称 + 净流出额）
    - 口径：东财/同花顺「行业资金流向」；与「板块涨跌幅 TOP」不是同一栏，不要互相替代

**推荐抓取入口**（WebFetch / 搜索均可，优先东财）：

- 大盘资金流向：`https://data.eastmoney.com/zjlx/`
- 行业资金流：`https://data.eastmoney.com/bkzj/jlr.html`（或同花顺资金流向·行业）
- 北向资金：`https://data.eastmoney.com/hsgt/index.html`（或搜索「北向资金 昨日净流入」）

**解读（1～2 句）**：结合量能 + 北向 + 主力行业，判断市场强弱与资金偏好（如「放量上涨但北向净流出 → 内资主导」）；对齐用户「主线科技/AI、跷跷板」；不作荐股。

### 2. 昨日板块复盘

用 **东方财富行业板块**（不是通达信 127，不要假装是通达信口径）的 **昨日收盘** 涨跌：

- 领涨行业 TOP 5～8（名称 + 涨跌幅）
- 领跌行业 TOP 5～8
- 一句结构解读（如科技 vs 银行白酒跷跷板）；对齐用户「主线科技/AI」世界观，但不编造因果
- 章节标题用：`## 昨日板块复盘（东财行业）`

### 3. 昨日持仓复盘

对 `data/raw/trades/` 中每只 A 股持仓，用 **昨收** 复盘：

- 成本、昨收、浮盈亏（金额与比例）
- 相对 **5 日均线**位置；是否接近用户止损纪律（有效跌破 5 日线 / 趋势线）
- 对照四选一买卖习惯：不建议无买点加仓；已加速则提醒勿追
- 无 A 股持仓则写「当前无 A 股持仓记录」
- 章节标题用：`## 昨日持仓复盘`

### 4. 持仓负面消息提醒（有持仓则必做）

对每只 **A 股持仓**（代码 + 简称），用 WebSearch 查 **近 7 日**是否有负面/风险类新闻；无持仓则跳过并写「无持仓，跳过」。

- 章节标题用：`## 持仓负面消息提醒`
- 搜索关键词组合示例：`{简称 OR 代码} + (减持|立案|处罚|问询|业绩预亏|亏损|诉讼|违规|暴雷|停牌|监管)`；可按标的合并为 1 次搜索以控成本
- 中文源优先：财联社 / 华尔街见闻 / 金十 / 巨潮·公司公告转述；查到公告类优先于自媒体
- **每只标的必须有结论**，二选一：
    - **有负面**：1～3 条，每条：要点 + 来源 + 日期；标严重度（高/中/低）；事实与解读分开；明确是否可能冲击开盘/止损纪律
    - **未见明显负面**：写「近 7 日未见明显负面（检索覆盖有限，置信度：中）」——**禁止省略、禁止用宏观要闻代替个股扫描**
- 不编造；搜不到写「未获取」；正面利好不要写进本栏（利好可并入要闻或省略）
- 持仓超过 3 只时仍全部扫（用户上限本就 ≤3）

### 5. 当日盘前要闻（必做，不可省略）

用 WebSearch 抓 **3～5 条**与 A 股相关、**当日 09:00 前发布/更新**的最新要闻（政策、宏观数据、流动性、地缘、重要产业、隔夜外盘）：

- 必须单独成章，标题用：`## 当日盘前要闻（09:00 前）`
- 优先选标题带「盘前」「早报」「要闻速递」的今日文章；若只能搜到隔夜外盘/晚间政策，须标明发布时间
- **引用格式硬性要求**：每条必须标注 **具体发布时间（精确到分钟）+ 来源**，格式统一为：
  `YYYY-MM-DD HH:MM 来源名`
  示例：`2026-08-05 08:47 新华财经`
    - 优先 WebFetch 原文页核对发布时间；搜索摘要只有日期不够
    - 只有日期、没有时分：须再查；仍查不到则写 `YYYY-MM-DD 时刻未核实 来源名`，并标置信度：低——**禁止假装精确到分钟**
    - 禁止只写「来源」或「今日早上」而不带时间戳
- 每条建议结构：`**标题要点** — YYYY-MM-DD HH:MM 来源。事实。解读：…`
- 事实与解读分开；查不到写「未获取」，不编造
- 至少覆盖：流动性/央行或宏观政策 **1 条** + 产业或外盘相关 **1 条**（有则写）
- **不要**用昨日盘中已消化完的旧闻凑数（除非仍影响今日开盘预期，并标明为背景）

### 6. 今日应对（必须有）

用独立章节 **「今日应对 / 意见与建议」** 收尾，基于 **市场状态评分/策略档** + 昨日复盘 + **资金面结构** + 持仓负面提醒 + 盘前要闻给可执行观点：

- 今日仓位倾向必须与「市场状态判断」的对应策略一致（防守/轻仓试错/积极参与/进攻），并一句说明是否因持仓个股/负面新闻微调
- 持仓个股：持有 / 警惕止损 / 勿加仓 等明确态度（若有负面新闻，态度须点名是否因此提高警惕）
- 1～2 个观察点（指数或板块），不要荐股清单、不要替用户选股

## 飞书通知（必须做）

**不要发邮件**（Resend 已停用）。用飞书自定义机器人 Webhook 推送：

1. Webhook URL = 本 Instructions 文末「密钥」段的 `FEISHU_WEBHOOK_URL`（只存在 Automations UI，不进仓库）
2. **必须推送与仓库 md 等价的完整正文**（不是三四行摘要）。用户要在飞书里直接看完盘前内容。
3. 推荐用 Python 读已写好的 md 再 POST（避免手工删减、也避免 JSON 转义出错）：

```bash
python3 - <<'PY'
import json, os, urllib.request
path = "output/daily/ashare-premarket-YYYY-MM-DD.md"  # 换成当天真实路径
url = os.environ.get("FEISHU_WEBHOOK_URL") or "PASTE_FROM_INSTRUCTIONS"
text = open(path, encoding="utf-8").read().strip()
# 自定义机器人请求体上限约 20KB；超长则保留标题+尽量多正文并注明截断
max_chars = 5500
if len(text) > max_chars:
    text = text[:max_chars] + "\n\n…（已截断，全文见仓库同名 md）"
body = json.dumps({"msg_type": "text", "content": {"text": text}}, ensure_ascii=False).encode("utf-8")
req = urllib.request.Request(url, data=body, headers={"Content-Type": "application/json"})
print(urllib.request.urlopen(req).read().decode())
PY
```

若 Instructions 里的 URL 未注入环境变量，把上面 `url = ...` 改成直接使用文末密钥中的完整 Webhook 字符串。
4. 成功：响应含 `"code":0`（或旧版 `"StatusCode":0`）
5. 失败：运行摘要写明错误，仍保留 md + commit
6. **禁止**只发「市场状态一句话 + 今日应对一句话」这种极简版；至少覆盖 md 里各一级章节的完整要点
